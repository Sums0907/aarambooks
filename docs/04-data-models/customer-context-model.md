# Customer Context Model

> [!WARNING]
> **LEGACY TRANSITIONAL MODEL**
> Under the Stage F Generic Context Capability Framework, Brain Core no longer defines or owns physical data schemas. The `CustomerContext` model documented here exists strictly as a legacy transitional dependency required by Event Bus orchestration and will be migrated to the Customer Query domain/CEM boundary in the future. It is not part of the Generic Context Protocol.

## 1. Purpose

The Customer Context Model provides the structural representation of the customer involved in an interaction. It ensures the intelligence domain has access to necessary identity, relationship, and historical interaction data.

## 2. Responsibility Boundary

The Context Engine does not maintain a master customer database. It relies on the `CustomerContext` generated by external adapters (e.g., ShopDeck) and passes it unchanged to intelligence domains.

## 3. Data Structure

```python
class CustomerContext(FrozenContextModel):
    customer_id: Optional[str] = None
    interactions: List[str] = Field(default_factory=list)
    needs: List[str] = Field(default_factory=list)
    previous_conversations: List[str] = Field(default_factory=list)
    resolution_history: List[str] = Field(default_factory=list)
    relevant_business_situations: List[str] = Field(default_factory=list)
```
