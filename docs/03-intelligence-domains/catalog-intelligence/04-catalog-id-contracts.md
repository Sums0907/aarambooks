## 1. The Interaction Boundary

Catalog ID has **zero direct database access** to Catalog BS. It interacts strictly via authorized interfaces.

- **Discovery Phase:** Reads canonical facts via `vw_catalog_master`, `vw_catalog_products`, and `vw_catalog_skus`.
- **Command Phase:** Submits mutations via the `SaveProductFamily` contract.

---

## 2. Product Attachment Contract

The command semantics generated by Catalog ID must explicitly target one of three operations.

### 2.1 Operation: `NEW PRODUCT FAMILY`
- **Definition:** Catalog ID determines the candidate represents a distinct offering.
- **Supplied Identity:** None (`product_internal_id` omitted; Catalog BS will generate the UUID).
- **Proposed Identity:** `product_code` and `sku_id`.

### 2.2 Operation: `ATTACH NEW SKU TO EXISTING PRODUCT`
- **Definition:** Catalog ID determines the candidate is a variant of an existing family.
- **CRITICAL INVARIANT:** Catalog ID **MUST** resolve the authoritative `product_internal_id` (UUID). A matching `product_code` string is **NEVER** sufficient to attach a SKU.
- **Supplied Identity:** `product_internal_id` (mapped from `DISCOVERED_CANONICAL`).
- **Proposed Identity:** `sku_id`.

### 2.3 Operation: `UPDATE EXISTING SKU`
- **Definition:** Modifying attributes of an existing SKU.
- **Supplied Identity:** `sku_internal_id` and `product_internal_id`.
- **Proposed Identity:** None. Identifiers cannot be blindly mutated.

## 3. Stale State Semantics & Concurrency

Catalog BS is a concurrent system. Time passes between Catalog ID discovering truth, reasoning, and generating a command.

- **Revalidation Limitations:** Revalidating public views reduces stale-state risk, but it does **NOT** guarantee a race-free snapshot.
- **Final Concurrency Authority:** Catalog BS remains the final concurrency authority.
- **Rejection Mandate:** A perfectly valid Catalog ID decision may still receive a `SKU_COLLISION`, `PRODUCT_CODE_COLLISION`, `CROSS_PRODUCT_SKU_MUTATION_DENIED`, or other validation rejection. Such rejection **MUST NOT** be treated as a Catalog BS inconsistency or system failure merely because Catalog ID previously observed a different state. The Catalog BS rejection is absolute.
