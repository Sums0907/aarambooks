# R-7 Action Payload Final Mapping Audit

## 1. Executive conclusion
BLOCKED

While Brain Core provides the capability for `NormalizedParameter` scalar delivery, several critical structural issues prevent immediate, safe implementation of R-7 adapters for all 7 capabilities. Specifically, R-5 is missing the `supplier` entity resolver, and several Domain Services require explicit document identifiers (like `grn_number` and `return_number`) that R-7 is architecturally forbidden to invent, but which are not currently guaranteed by the Brain Core semantic contract.

## 2. Architectural rule
R-5 resolves entities.
Brain Core supplies normalized scalar parameters.
R-7 constructs domain DTOs and invokes authoritative services.
R-7 must not invent business facts, identifiers, timestamps, or enum values merely to satisfy a schema.
Domain services retain transaction/business-rule authority.

## 5. Document/reference generation analysis
- **grn_number**: Supplied by caller. Domain does not generate.
- **return_number**: Supplied by caller. Domain does not generate.
- **reference_document (Transformation)**: Supplied by caller. Domain does not generate.
- **issue_reference (Job Work Issue)**: Generated by Domain (`JW-ISS-...`).
- **return_number (Job Work Return)**: Generated by Domain (`JWR-...`).
- **movement_number (Stock Adjustment)**: Supplied by caller. Domain does not generate.
- **reference_id / reference_type (Stock Adjustment)**: Supplied by caller. Domain does not generate.

## 6. R-5 dependency audit
- `inventory.entity.warehouse`: Resolver exists (`warehouse_resolver.py`).
- `inventory.entity.sku`: Resolver exists (`sku_resolver.py`).
- `inventory.entity.job_worker`: Resolver exists (`job_worker_resolver.py`).
- `inventory.entity.exception`: Resolver exists (`exception_resolver.py`).
- **`inventory.entity.supplier`**: **MISSING**. No `supplier_resolver.py` exists. Both Goods Receipt and Purchase Return rely on this.

## 7. Brain Core parameter audit
- `quantity`: Maps to `inventory.numeric.quantity`.
- `receipt_date` / `movement_date`: Maps to `inventory.temporal.posting_date`.
- `resolution_notes`: Maps to `inventory.text.resolution_notes`.
- **`grn_number`, `return_number`, `movement_number`, `reference_number`**: These must map to `inventory.document.reference` or similar. Brain Core currently lacks a guaranteed contract for extracting random, unformatted strings as authoritative document identifiers.
- **`movement_type`, `reference_type`**: These are internal structural enums. It is highly doubtful Brain Core can reliably map user intent directly to the exact schema enum string without an adapter mapping layer.

## 8. Dangerous assumptions rejected
- **Auto-generating GRN/return numbers**: REJECTED. R-7 must not invent business document identifiers just to satisfy Pydantic. If Brain Core doesn't supply it, the capability is blocked.
- **Using warehouse_id as reference_id**: REJECTED. The domain must be invoked correctly. Tests show reference_ids can be separate semantic entities.
- **Inventing quantities/dates**: REJECTED. R-7 cannot use `date.today()` if the semantic payload lacks a date.
- **Assuming supplier resolver exists**: REJECTED. Forensic audit confirms it does not exist.

## 9. Capability status
1. Goods Receipt: **BLOCKED** (Missing `supplier` R-5 resolver, missing `grn_number` generation authority).
2. Purchase Return: **BLOCKED** (Missing `supplier` R-5 resolver, missing `return_number` generation authority).
3. Transformation: **BLOCKED** (Missing `reference_document` generation authority).
4. Job Work Issue: **READY** (Domain generates reference, R-5 dependencies exist).
5. Job Work Return: **READY** (Domain generates reference, R-5 dependencies exist).
6. Exception Resolution: **READY** (R-5 dependency exists, takes raw scalar parameters).
7. Stock Adjustment: **BLOCKED** (Requires complex internal enum mapping and `movement_number` generation authority).

## 10. Final R-7 readiness
**R-7 IMPLEMENTATION IS BLOCKED.**
R-7 architectural mapping cannot proceed safely for all capabilities. While `JobWorkIssue`, `JobWorkReturn`, and `ExceptionResolution` are structurally sound, the core capabilities (`GoodsReceipt`, `PurchaseReturn`, `StockAdjustment`) are blocked by missing R-5 resolvers and missing clarity on document-identifier generation authority.
