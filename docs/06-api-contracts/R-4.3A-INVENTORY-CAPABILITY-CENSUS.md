# RABTA R-4.3A — COMPLETE INVENTORY CAPABILITY CENSUS

## Final Status
**R-4.3A CAPABILITY SURFACE EXHAUSTIVELY IDENTIFIED**

## 1. Scope and Methodology
This census was conducted by exhaustively searching the `Aaram_Inventory` repository, cross-referencing:
- Capability URN strings globally (`grep_search`)
- Stage F capability registry (`ContextEngine`)
- Subclasses of `BaseCapabilityHandler`
- API boundaries (`cem_router.py`, `context_router.py`, `read_api_router.py`, `master_data_router.py`)
- Business domain services (`src/domains/inventory/services/*`)
- Repositories and internal engines (e.g., `ConfidenceEngine`, `TransformationEngine`)

## 2. Complete Discovered Capability Inventory
The search identified 12 distinct operations/capabilities across the repository:
1. **Inventory Balance Retrieval**: Reads real-time balance.
2. **Inventory Ledger Retrieval**: Reads chronologically ordered inventory movements.
3. **Jobwork Status Retrieval**: Reads custody ledger for items issued to a job worker.
4. **Exception Status Retrieval**: Reads unhandled discrepancies and open inventory exceptions.
5. **Goods Receipt Creation**: Registers new incoming stock via PO/ASN.
6. **Purchase Return Creation**: Removes defective/returned stock.
7. **Inventory Transformation**: Converts BOM components into finished goods (Job Work / In-House).
8. **Job Work Issue/Return**: Moves inventory custody to/from a supplier.
9. **Exception Resolution**: Post-facto resolution of system/physical discrepancies.
10. **Balance Recalculation**: Internal calculation to reset snapshot tables.
11. **Confidence Calculation**: Internal scoring of record reliability.
12. **Master Data Import/Export**: Bulk ingestion of catalogs.

## 3. Cross-Source Reconciliation
- **Capability Registry / Handlers / URNs**: 4 exactly overlapping artifacts (`balance`, `ledger`, `jobwork_status`, `exception_status`).
- **Context API Routes**: 4 routes corresponding 1:1 with the defined URNs.
- **Read APIs**: `/inventory/balance` exposes the balance capability via HTTP outside Stage F.
- **Business Domain Services**: Expose the 4 RETRIEVE capabilities, 5 ACTION operations without legacy handlers, and 3 internal utilities.
*Discrepancies*: There are no discrepancies between Stage F definitions and URNs. However, domain services expose 5 state-changing actions that have never been mapped to capability handlers.

## 7. AaramIdentity Boundary
All discovered Stage F capabilities securely rely on application context injected by the API layer. The legacy `ContextCapabilityRequest` correctly omits `AaramIdentity` tokens. The R-4 endpoints (`cem_router.py`) must continue to extract `AaramIdentity` application context out-of-band and never leak it into the `AbstractEvidenceRequest`.

## 8. CEM ID / CEM URN Routing Boundary
The existing repository isolates CEM selection entirely. Nowhere in the `BaseCapabilityHandler` subclasses or the Inventory domain services is `cem_urn` or CEM ID referenced. CEM routing remains successfully outside R-4 business applicability.

## 9. Legacy Stage F Mapping
Stage F `ContextEngine` accurately maps the 4 existing RETRIEVE capabilities via `ContextContainer`. This legacy mechanism is fully self-contained and does not bleed into R-4 domains.

## 10. Missing/Undocumented Capabilities

## 12. Architectural Decisions Required
**Multiple Capability Resolution for `RETRIEVE`:**
Because a semantic request supplying `sku` technically satisfies the baseline requirement for `Ledger`, `Exception Status`, and partially `Balance`, multiple capabilities can logically map to one request. While `capabilities_discovered: List[str]` permits multiple URNs in the response, `evidence_data: Dict[str, Any]` is singular. 
*Decision Required:* Does the generic contract dictate that multiple RETRIEVE matches return an `EXECUTION_LIMITATION`, or does it expect merged evidence keys?

**ACTION Capability Exposure:**
*Decision Required:* Should state-changing operations (Transformation, Goods Receipt) be formally designed as R-7 CEM capabilities in this phase, or are we strictly focusing on the 4 RETRIEVE capabilities?
