# Sarvam VoiceBot Integration Contract (V2)

This document serves as the master integration contract for Sarvam AI as the voicebot provider for the Aaram Brain NDR Engine. It outlines the architecture, authentication, and the strict input/output variables exchanged between the Brain and the Sarvam edge agents.

## 1. Architectural Overview

- **Protocol**: Instant Outbound API (Supersedes the deprecated Stream Cohorts/Campaigns model).
- **Execution Pattern**: Single-call API request (`POST https://apps.sarvam.ai/api/outbounds/v1/orgs/{org_id}/workspaces/{workspace_id}/outbounds`). The Brain dispatches the call passing all context variables upfront. Exactly ONE completion webhook is fired upon call termination.
- **Webhook Endpoint**: `POST /api/customer-engagement/voice/sarvam/call-completed`
- **Authentication**: Because Sarvam's `webhook_config` does not natively support header-based authentication, the Brain relies on a query parameter token (`?secret=SARVAM_WEBHOOK_SECRET`) securely embedded in the webhook URL.

## 2. Input Variables (Hydration Payload)

These are the context variables generated by `ccc_builder.py` and passed to Sarvam in the Instant Outbound request via `app_config.agent_variables`. 

*Security Guardrail: Internal system IDs (`engagement_id`, `action_request_id`) are passed for correlation but are explicitly excluded from the LLM prompt to prevent internal ID leakage to the customer.*

### Core Routing & Correlation
- `engagement_id`: Unique identifier for the Brain engagement session.
- `action_request_id`: Tracing ID for the outbound queue.
- `awb_no`: The tracking number.

### Customer & Order Context
- `customer_name`: Full name of the recipient.
- `destination_pincode`: Pincode for address verification guardrails.
- `order_date`: Original date of purchase.
- `payment_mode`: e.g., `cod` or `prepaid`.
- `collectable_amount`: The exact amount due to the delivery executive.
- `order_quantity`: Number of items in the shipment.

### Product Intelligence
- `product_category`: Broad category (e.g., Bedsheet Set).
- `product_name`: Full marketing name.
- `product_description`: Full marketing description used to answer product queries.
- `size`: Exact dimensions.
- `color`: Primary color.
- `material`: Fabric and thread count.
- `features`: Key selling points.
- `attr_style`, `attr_pattern`, `attr_package_contents`: Detailed aesthetic properties.
- `mrp`: Maximum Retail Price.
- `catalog_selling_price`: Reference price.
- `actual_item_price`: The exact amount the customer paid.
- `return_exchange_condition`: The applicable return policy.

### Delivery Diagnostic
- `courier_partner`: The logistics provider (e.g., Delhivery, Amazon DS).
- `past_delivery_attempts`: Number of failed attempts.
- `prior_communication_summary`: Summary of IVRs, SMS, or WhatsApps already sent.
- `context_summary`: The situation (e.g., "customer unavailable, parcel at hub").
- `objective`: The goal of the call.
- `mission_why_this_call`: Context for the agent on why this is urgent.
- `diagnostic_priority_instruction`: Instructions to extract the root cause of failure.
- `offered_reattempt_date_1` & `offered_reattempt_date_2`: The strict constraints on what dates can be offered.

## 3. Output Variables (Final Agent Variables)

Unlike earlier voicebot architectures that required the Brain to run expensive, real-time LLM parsing on raw transcripts, the Sarvam V2 integration uses edge-native intelligence. The Sarvam agent extracts the intent directly at the edge, and passes the structured outcome back to the Brain inside the `payload.final_agent_variables` JSON block.

| Variable | Type | Possible values | Captured for |
| --- | --- | --- | --- |
| `call_summary` | string | free text | Summary of the call |
| `reattempt_date_selected` | string | free text (must match `offered_reattempt_date_1` or `2` exactly) | The reattempt date the customer picked, if any |
| `address_change_requested` | enum | `yes`, `no` | Whether the customer asked for an address change |
| `phone_no_change_requested` | enum | `yes`, `no` | Whether the customer asked for a phone number change |
| `call_outcome` | enum | `rescheduled`, `customer_declined`, `address_updated`, `phone_no_update`, `escalation_requested`, `no_resolution` | Overall disposition of the call |
| `new_address_details` | string | free text | Corrected address captured, if provided |
| `new_phone_number` | string | free text | Alternate phone number captured, if provided |

## 4. Completion Webhook Payload

When the call terminates, Sarvam fires a single `POST` to the Brain containing:
- `attempt_id`: The provider session ID.
- `status`: Final network status (e.g., `connected`, `no_answer`, `busy`, `failed`).
- `interaction_id`: Provider event ID.
- `interaction_transcript`: The full, turn-by-turn transcript (preserved in SABAQ for advanced intelligence).
- `failure_reason`: The telephonic error string if the call failed.
- `final_agent_variables`: The structured output variables (see Section 3) used by the Brain's writeback queue to update ShopDeck.
- `webhook_config`: Echoed back verbatim from the original creation request, guaranteeing the Brain receives the `metadata.engagement_id` for deterministic correlation.
